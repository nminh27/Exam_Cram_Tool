# Knowledge pack format (`finalforge-pack`, version 1)

A pack is one JSON file:

```json
{ "format": "finalforge-pack", "version": 1, "name": "Course name", "description": "", "knowledge": { ... } }
```

`knowledge` is exactly what the app stores in `data/courses/<id>/knowledge.json`. `samples/demo_pack.json`
(generated by `samples/build_demo.py`) is a complete, valid example. All text fields are Markdown with
LaTeX math (`$...$` inline, `$$...$$` display; a literal dollar is `\$`).

Who writes packs: students' own AI chats on the website (the prompt is `web/js/ai-prompt.js`; keep it in step with this
file), the app's Analyze pipeline, and Claude Code (`app/packkit.py`). On the website, `web/js/pack-clean.js` repairs
an imported pack (missing fields, ids, out-of-range answers, unknown references) and merges extra parts into a course;
ids a pack already has are kept, so saved progress survives a replaced pack.

## knowledge

| field | type | notes |
|---|---|---|
| `version` | 1 | |
| `course` | `{title, overview_md}` | the big-picture story + what the exam looks like |
| `topics` | `[{id, name, summary}]` | ids `t-...` |
| `concepts` | `[Concept]` | ids `c-...` |
| `patterns` | `[Pattern]` | ids `p-...`, sorted by `frequency` desc |
| `mcqs` | `[MCQ]` | |
| `guided` | `{concept_id: [GuidedStep]}` | Socratic discovery chains |
| `problems` | `[Problem]` | |
| `learning_path` | `[concept_id]` | every concept, prerequisites first |
| `uncovered_questions` | `[{material_id, number}]` | past-paper questions not mapped to a pattern |
| `generated_at`, `model` | | |

### Concept
`{id, name, topic_id, one_liner, prerequisites: [id], related: [id], importance: core|supporting|peripheral, source_refs: [str], exam_frequency: int, detail: ConceptDetail|null}`

ConceptDetail: `why_exists_md, what_it_does_md, how_it_works_md, everyday_analogy_md, visualize_md, diagram_svg,
atomic_steps: [{step_md, everyday_link}], formulas: [{latex, name, meaning_md, symbols: [{symbol, meaning, unit}], when_to_use_md}],
patterns_to_spot: [{cue, signals_md}], common_traps: [{trap_md, fix_md}], tips_tricks: [{tip_md, source}], mini_example_md, self_check: [str]`

`diagram_svg` is rendered through an `<img>` tag (scripts can't run); keep it small and self-contained.

### Pattern
`{id, name, description, calc: bool, concept_ids: [id], frequency: int, source_questions: [SourceQuestion], guide: Guide|null}`

SourceQuestion: `{material_id, number, text_md, marks, solution_md, material_label, is_exam}`

Guide: `{recognition_cues: [str], recipe: [{step_md, why_md, everyday_link}], tricks: [str], traps: [str], examiner_wants_md}`

### MCQ
`{id, concept_ids: [id], type: intuition|misconception|application|pattern|map, question_md, options: [str], correct: int (0-based), option_explanations: [str] (one per option), solution_md, difficulty: 1-3}`

`solution_md` is a numbered step-by-step working from the question to the right option (what is given, the idea or formula, each substitution, the result, then why the tempting wrong options fail). It is shown under "Step by step" once the question is checked. Packs without it still load (empty string).

Optional `figure_svg`: an SVG shown under the explanation once the question is checked (e.g. the spectrum that answers it). Rendered through `<img>` like `diagram_svg`; leave it out when there is no graph.

### GuidedStep
`{question_md, options: [str], correct: int, explanation_md}`

### Problem
`{id, pattern_id, source: past_paper|variant, source_ref, title, statement_md, parts: [Part], verified: bool|null, verify_note}`

Part: `{label, prompt_md, marks, final_answer_md, steps: [Step]}`

Step:

| field | notes |
|---|---|
| `id` | unique, e.g. `<problem id>-<part>-<step>` |
| `kind` | given, unknown, concept, formula, rearrange, substitute, compute, units, check, interpret, explain, final |
| `prompt_md` | short direct question |
| `answer_type` | `numeric` (typed number, checked with `tolerance_pct` relative tolerance), `choice` (one of `choices`), `multi` (exact set), `text` (AI-marked or self-marked against `text_answer_md`) |
| `choices`, `correct_choices` | 0-based indices; empty for numeric/text |
| `numeric_answer`, `tolerance_pct`, `unit` | numeric steps only (else `null`, `null`, `""`) |
| `text_answer_md` | model answer / marking points for text steps |
| `hint_md`, `explanation_md` | nudge without giving it away / full working and why |
| `concept_ids` | concepts this step exercises (drives mastery) |
| `figure_svg` | optional: an SVG of the worked answer (a sketch, tree, table), shown with the explanation once the step is answered or revealed |
